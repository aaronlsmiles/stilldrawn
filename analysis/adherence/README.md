# Adherence instrument (amendment A9, Test 1)

Two blind rating studies ask whether each clip did the motion its prompt asked for: `burst/` holds the 55 primary burst clips and `push/` the 55 primary camera-push clips, 22 clips per engine in all. They run on blindpanel 0.1.0. Amendment A9 in `docs/PREREGISTRATION.md` registers the wording, the raters and the analysis; this folder holds the instrument and, after rating, the ratings.

## Files

| File | What it is |
|---|---|
| `prepare.py` | Selects the cells, makes the rating copies, writes and checks the studies and their builds |
| `test_prepare.py` | Its tests: `python3 -m pytest analysis/adherence/test_prepare.py` |
| `burst/study.yaml`, `push/study.yaml` | The blindpanel studies: wording, seed, items. Generated by `prepare.py write` |
| `burst/study.lock.json`, `push/study.lock.json` | The hash of each study's wording (`blindpanel lock`) |
| `burst/banned-terms.txt`, `push/banned-terms.txt` | Names the page, its URLs and `reveal.json` must never contain: engine and model names, cell and panel ids, the old working name. Generated by `prepare.py write` |
| `burst/media-sources.json`, `push/media-sources.json` | Each rating copy's source, decoded-frame hash, encoding and own hash |
| `rating-copies.sha256` | The SHA-256 of all 110 rating copies |
| `build-trees.json` | The hash of each built study; each rating sitting checks its build against it |
| `ratings-<study>-<RATER>.json` | One rater's ratings, slimmed from the blindpanel export by `python3 analysis/a9_adherence.py slim` |
| `sessions.sha256` | The SHA-256 of every session row that is not analysed (a rater's extra sessions, one line per row) and of every rating file replaced after it was first written, one `<sha256>  <description>` line each; present once there is one |

Not released: the rating copies (`burst/media/`, `push/media/`), the raw exports (`raw/`), the local rating stores (`.data/`) and the builds (`.build/`).

## Rating copies

Each clip is scaled to cover and centre-cropped to 1280×704 (the portrait panel's clips to 704×1280). Its first 121 frames are kept at a constant 24 fps; a source at another rate would be retimed by frame timing, never relabelled (all 110 sources are 24 fps). Encoding is libx264 at CRF 16, yuv420p, with no audio, no container or stream metadata, and no encoder message. So no copy differs from another in size, frame count, frame rate, audio, metadata or embedded content credentials. `prepare.py check` proves this for every copy: ffprobe, the MP4 box structure, and a byte search for C2PA and JUMBF signatures. The image shown beside each clip is a PNG copy of its panel with the same pixels and no text chunks.

Encoding is deterministic for a given ffmpeg and libx264 build; `media-sources.json` records the ffmpeg version. Another build gives different bytes but equivalent pictures. `source_frames_sha256` ties each copy to its released clip through the decoded frames, which the release's metadata rewrites leave unchanged.

## Rating

Each rater rates alone and unobserved on the author's computer, through `blindpanel dev --store file` on localhost, in a fresh private browser window: one sitting per study, burst first. The page shows opaque codes only, every clip is labelled "clip", and the reveal shows nothing else. Each slim file keeps the order the rater saw, the scores, the day blindpanel stored (never the time), its flags (which exclude nothing) and the hash of the raw export.

The raters are AARON and R7, a new rater who has never rated for StillDrawn. Only the first complete session in a rater's store is analysed. `python3 analysis/a9_adherence.py set-aside --study <burst|push> --rater <AARON|R7> --store <store folder>` moves any other session row, unchanged, to `raw/<study>-<RATER>/extra-sessions.jsonl` (not released) and records one line per moved row in `sessions.sha256`: `<sha256 of the row's bytes as stored>  extra session <study>-<RATER> row <k> (<YYYY-MM-DD> UTC)`, where `k` counts the rows of that extra file. The hash covers the row exactly as the store held it, including its own line terminator; a final row stored without one is hashed without one and the extra file gets a separating LF after it. `slim --force` records the hash of the file it replaces there too.

`set-aside` needs care, because blindpanel's stored rows carry no rater:

- **Stop the blindpanel server first.** `set-aside` rewrites the store file, and a running `blindpanel dev` could write to it at the same moment. The command refuses a store file modified in the last 120 seconds, but that is a safety net, not a lock.
- The store folder's name must equal `--rater` (the default layout is `.data/<RATER>`); any other name is refused.
- A row whose `study` is not `a9-<study>` is refused, not moved. A line that is not a complete session (including one that parses to JSON `null`) is moved, never kept; only an empty or whitespace-only line is left alone.

## Pilot

On 2026-10-30 a scripted pilot ran the whole path (copies, build, serve, submit, export, slim) on six clips from amendments A3 and A4 only, with the burst wording and fixed answers entered by a headless browser. No person rated and no clip was watched. Every pilot file was deleted afterwards.
